# Backend stack evaluation for a self-hosted, LAN-playable SIGame server (as of 2026-09-18)

Кратко по-русски: рекомендуемый стек — **Bun 1.4.2 + Hono 4.13 + Zod 4 + bun:sqlite/Drizzle + Scalar**, один бинарник на Win/macOS/Linux через `bun build --compile`. Ближайшая "скучная и надёжная" альтернатива — **Go 1.27 + chi + huma + coder/websocket + modernc.org/sqlite**. Ниже — полное сравнение с проверенными версиями и источниками.

## 2. What actually drives the decision for this project

1. **Buzzer latency**: 5–20 LAN clients; any stack delivers sub-millisecond server work. Fairness is a *protocol* problem (server-arrival timestamps + per-client RTT/offset compensation + a short collection window), not a language problem. All stacks below can do it; what matters is cheap access to hrtime, ping/pong RTT and pub/sub.
2. **Media with HTTP Range** (audio/video on iOS Safari refuses to play without 206 support): Go `http.ServeContent`, Rust `tower-http 0.7 ServeDir`, Bun `Bun.file()` bodies, Node `@fastify/static` all handle it — but framework wrappers can silently break it (see Elysia issue #1868).
3. **Single binary on 3 OSes from one dev machine**: Go and Bun cross-compile trivially; Rust needs `cross`/`cargo-zigbuild`; Node SEA is still Stability 1.1 and officially discourages cross-platform builds; Python (PyInstaller) must be built on each OS.
4. **.siq = ZIP + content.xml (schema `siq_5.xsd`) + Images/Audio/Video/Html + [Content_Types].xml**. Every stack has zip+xml; Go/Python/Rust have it in stdlib or first-tier crates, TS uses fflate/yauzl + fast-xml-parser.
5. **Shared types with the (almost certainly TypeScript) web client**: only the TS stacks give you one Zod schema for REST body + WS message + OpenAPI + client types.

## 3. Per-stack evaluation

### 3.1 TypeScript on Bun 1.4 — Hono / Elysia / raw Bun.serve

**Runtime state.** Bun 1.4.0 (2026-08-20) is the first Rust-based Bun: the Zig codebase (~535k lines) was ported with Claude agents in May 2026; Bun reports 128 bugs fixed vs 1.3.14, ~2–5% faster, ~20% smaller binaries, up to 35% less memory, 5x less idle CPU, 50% faster start on Linux, Node.js compat target 26.3.0, experimental HTTP/2+HTTP/3 in `Bun.serve`. 19 regressions were caught pre-ship; 1.4.1 and 1.4.2 then fixed further regressions (a `bun build` rename bug that broke Elysia apps, an AsyncLocalStorage leak, GC/JIT crashes). Bun has been owned by Anthropic since 2025-12-02 (MIT, same team; Claude Code ships as a Bun executable, so the runtime is strategically funded). Windows ARM64 is native since 1.3.10.

**WebSockets.** `Bun.serve({ websocket })` is uWebSockets-based: topic pub/sub (`ws.subscribe/publish`, `server.publish`), `send()` returns backpressure status (-1/0/bytes), `maxPayloadLength` (16 MB default), `idleTimeout` (120 s), `perMessageDeflate`, `backpressureLimit`, typed `ws.data`, `pause/resume` (1.3.13). Bun's own chatroom benchmark: ~700k msg/s vs ~100k for Node+ws (7x). Independent Socket.IO benchmark (Jan 2026): Node+uWS wins raw throughput, Bun wins memory.

**Range streaming.** Bun docs: for file/directory routes "Range requests are supported with `Accept-Ranges: bytes` and `Content-Range`", and `Bun.file().slice(start,end)` auto-sets `Content-Range`/`Content-Length`. Caveat: the association is lost if a framework re-wraps `response.body` as a ReadableStream (this is exactly what broke Elysia 1.4.23+/`@elysiajs/static` on iOS). With Hono, return `new Response(Bun.file(p))` from the handler directly and test with Safari.

**SQLite.** `bun:sqlite` is built in (sync, better-sqlite3-style, ~3–6x faster than better-sqlite3 in Bun's numbers, no native addon → no packaging issues); `Bun.SQL` also accepts `sqlite://`/`file://`/`:memory:` with an async tagged-template API. Drizzle 0.45.2 has a first-class `bun:sqlite` driver.

**Zip/XML.** No native zip in Bun (`Bun.Archive` is tar/gzip only). Use `fflate` 0.8.3 (in-memory + streaming, 8 kB) or `yauzl` 3.4.0 / `yazl` 3.3.1 for streaming large video packs; `fast-xml-parser` 5.11.1 for `content.xml` (parse and build, `preserveOrder` to keep script/param ordering).

**Single binary.** `bun build --compile --target=bun-{windows-x64|darwin-arm64|darwin-x64|linux-x64|linux-arm64|windows-arm64}` cross-compiles from any host; `--asset` (1.4) embeds directories (the web client), `--bytecode` works with ESM/top-level await; ~60 MB binary (83 MB with bytecode) vs ~115 MB for Node SEA in a Feb 2026 comparison.

**Cold start / memory.** ~9 ms to first request vs ~41 ms Node 22; idle RSS ~18–45 MB (vendor and third-party 2026 numbers) vs 60–75 MB for Node.

**Frameworks:**
- **Hono 4.13.8** — Web-standard, runtime-agnostic, backed by Cloudflare-employed maintainer, very large adoption. OpenAPI: `@hono/zod-openapi` 1.6.3 (Zod 4, OpenAPI 3.1) or `hono-openapi` 1.3.3 (Standard Schema); `@scalar/hono-api-reference` 0.12.2 mounts Scalar UI. WebSockets: `upgradeWebSocket` from `hono/bun` (onOpen/onMessage/onClose/onError); pub/sub needs `ws.raw as ServerWebSocket` (typed `unknown`, issue #3327) — thin but workable; or simply pass `websocket:` straight to `Bun.serve` and keep Hono for HTTP only. Node adapter `@hono/node-server` 2.1.1 now has built-in WS, so the code can move to Node if needed.
- **Elysia** — best DX for this exact job (route schemas → OpenAPI automatically, `fromTypes()` generates OpenAPI from TS types with no schema at all, `.ws()` routes with validated `message` schemas, Scalar UI built into `@elysiajs/openapi` 1.4.16, Bun-native pub/sub). But: 1.4.x now receives *security fixes only*; 2.0 is beta (`elysia@next`, 2.0.0-beta.16) with breaking changes (options-before-handler, WS becomes opt-in generator syntax, error API redesign, TypeBox 1.x), no stable date; the static plugin's Range regression (#1868) hit the media path this project depends on; effectively single-maintainer.
- **Raw `Bun.serve` routes** — fastest and simplest for WS, but you'd hand-roll OpenAPI; not recommended alone, though its WS handler is what I'd use underneath Hono.

**Ecosystem risk.** Medium: a very young Rust port (1 month old at time of writing) plus corporate ownership. Mitigation: pin `1.4.2`, keep `1.3.14` (last Zig build) as rollback, run `bun test` on all three OSes in CI.

### 3.2 TypeScript on Node 24 LTS / 26 — Fastify 5, NestJS 12

**Node state.** 24.21.0 is Active LTS (maintenance from 2026-10-20, EOL 2028-04-30); 26.9.0 becomes LTS on 2026-10-28 (V8 14.6, Temporal on by default, undici 8; `--experimental-transform-types` removed, so `enum`/`namespace` in .ts files no longer run natively — type stripping only). `node:sqlite` is **Stability 1.2 Release Candidate** (DatabaseSync, prepared statements, extensions, backup). SEA is **Stability 1.1 Active development**: `--build-sea` (25.5+) single-step build, ESM, assets, VFS (26.9) — but cross-platform SEA requires `useCodeCache`/`useSnapshot` off and is not recommended; native addons must be written to a temp file and `dlopen`ed (irrelevant if you use `node:sqlite`).

**Fastify 5.12.5** + `@fastify/websocket` 11.3.1 (`ws` 8.21.3 underneath; no built-in pub/sub, hand-roll a room map) + `@fastify/swagger` 9.8.1 + `@scalar/fastify-api-reference` 1.69.0 + `fastify-type-provider-zod` 7.0.0 (uses Zod 4.2 `encode/decode`) + `@fastify/static` 10.1.4 (Range via `send`). Fastify 6 is at alpha.4 — expect a major within months. Zip/XML same as Bun (`fflate`/`yauzl`, `fast-xml-parser`). Pi-5 measurement (Node 24 + Fastify 5.8.5): 68 MB idle RSS, 181 ms startup, p99 53 ms on SQLite CRUD.

**NestJS 12.0.3** — ESM, Standard Schema in decorators, `@nestjs/swagger` 12.0.1, `@nestjs/platform-ws` 12.0.3. Powerful but heavy (DI, decorators, modules, gateways) for a solo LAN game server; the v12 toolchain migration (Vitest/oxlint/Rspack) is fresh. Requires Node ≥20.19/22.12.

**Ecosystem risk.** Lowest of the TS options for the runtime itself; framework churn (Fastify 6, NestJS 12) is the main noise. Single-binary story is the weakest of the compiled/Bun options.

### 3.3 Go 1.27 — chi/Fiber + coder/websocket + huma/ogen

**Language.** Go 1.27.1 (Aug 2026): generic methods, `encoding/json` backed by json/v2 by default (faster Unmarshal; stricter UTF-8/duplicate-key rules — relevant when parsing user-authored packs), ML-DSA, allocation speedups; 1.26 shipped the Green Tea GC and ~30% cheaper cgo.

**HTTP/OpenAPI.** `chi` v5.3.2 (idiomatic `net/http`) or Fiber v3.5.0 (stable since 2026-02-11, Go ≥1.25, fasthttp-based — avoid for WS/Range simplicity). **huma v2.39.1** generates OpenAPI 3.1 + JSON Schema from typed request/response structs and ships **Scalar** (`huma.DocsRendererScalar`), SwaggerUI or Stoplight Elements — this is the closest Go equivalent to Hono+zod-openapi. `ogen` v1.24.0 is spec-first codegen (write OpenAPI, generate server+client) — good if you want the OpenAPI doc to be the contract; `swaggo/swag` (1.16.6, 2025) is comment-driven and dated.

**WebSockets.** `coder/websocket` v1.8.15 (context-aware, concurrent-write-safe, pure Go, actively maintained; gorilla archived) — you write the hub/room broadcast (a goroutine + channel per room, or a mutex-guarded map); `lxzan/gws` v1.10.2 if you want higher raw throughput. No built-in pub/sub anywhere, but a 20-player room is trivial.

**Range/media.** `http.ServeContent`/`ServeFile` handle Range, If-Range, If-Modified-Since and content-type sniffing in stdlib.

**Zip/XML/SQLite.** `archive/zip`, `encoding/xml` in stdlib. SQLite: `modernc.org/sqlite` v1.59.0 (pure Go, `CGO_ENABLED=0`, ~2x slower on CPU-bound work — irrelevant here), `ncruces/go-sqlite3` v0.35.5 (wasm, also cgo-free), or `mattn/go-sqlite3` v1.14.52 (cgo, fastest, but complicates cross-compiling).

**Single binary.** `GOOS=windows GOARCH=amd64 go build` from any host with `CGO_ENABLED=0`; static ~10–15 MB; `embed` the web client. Best-in-class.

**Cold start / memory.** Pi-5 study (Go 1.26.2, net/http): 9.6 MB idle RSS, 19.7 MB peak, 11 ms startup.

**Ecosystem risk.** Minimal; Go 1 compatibility promise, stdlib-heavy design. Cost: no shared TS types (generate with `openapi-typescript` from the served spec), more boilerplate, manual concurrency discipline.

### 3.4 Rust 1.98 (edition 2024) — Axum 0.8 + utoipa 5

axum 0.8.9 (WS via `axum::extract::ws`, tokio-tungstenite 0.30) + `utoipa` 5.5.0 with `utoipa-axum` 0.2.0 (router-integrated OpenAPI) and `utoipa-scalar` 0.3.0; `tower-http` 0.7.1 `ServeDir` now honors Range; `rusqlite` 0.40.2 (`bundled`, sync — wrap in `spawn_blocking`) or `sqlx` 0.9.0 (async, compile-time checked); `zip` 8.6.0 (9.0 pre-release) + `quick-xml` 0.42.0 (serde derive, new `&str` ergonomics). Binaries ~5–10 MB; cross-compiling needs `cross`/`cargo-zigbuild` or per-OS CI. Best efficiency measured: 4.97 MB idle RSS, 11 ms startup, p99 48 ms (Rust 1.95/axum 0.8.9 on Pi 5). Risk: crate churn (axum 0.x majors, utoipa-axum still 0.2), long compile times, and shared mutable room state under async borrows slows a solo developer more than the other options; no shared TS types.

### 3.5 Python 3.14 — FastAPI 0.141 + websockets

FastAPI 0.141.1 (Pydantic v1 support deprecated), Starlette 1.6.0, uvicorn 0.53.0, `websockets` 17.1, `scalar-fastapi` 1.9.0; `zipfile`, `xml.etree`, `sqlite3` in stdlib; Starlette's `StaticFiles`/`FileResponse` support Range. Excellent OpenAPI DX (Swagger/ReDoc built in, Scalar via plugin). Weak points for this project: heaviest footprint (Pi-5 study: 216 MB idle, 472 ms startup, p99 590 ms with Granian — an order of magnitude worse than Go/Rust), PyInstaller 6.22.3 cannot cross-compile (build on each OS, large bundles), free-threaded 3.14t still has ecosystem gaps (httptools/pydantic/orjson noted), no shared TS types.

## 5. Ranked recommendation

1. **Bun 1.4.2 + Hono 4.13.8 (Zod 4 + @hono/zod-openapi + Scalar, bun:sqlite + Drizzle 0.45, Bun.serve WebSockets)** — one language and one Zod schema for REST, WS protocol, OpenAPI and the client; uWS-grade WebSockets with pub/sub and backpressure out of the box; SQLite with no native-addon packaging pain; automatic Range on `Bun.file`; cross-compiled single executables for all five targets from one laptop; ~10 ms start, tens of MB RSS. Hono is the stable, widely-adopted framework layer; Bun is the risk, mitigated by pinning and a 1.3.14 fallback.
2. **Go 1.27.1 + chi 5.3.2 + huma 2.39.1 (Scalar renderer) + coder/websocket 1.8.15 + modernc.org/sqlite 1.59.0** — choose this if "boring and permanent" beats "fast to iterate": stdlib zip/xml/Range, `CGO_ENABLED=0` static ~10 MB binaries, 10 MB RSS, no ecosystem drama. Generate client types with `openapi-typescript` from the served spec.
3. **Node 24 LTS (→26 LTS on 2026-10-28) + Fastify 5.12 + fastify-type-provider-zod 7 + @fastify/swagger + @scalar/fastify-api-reference + node:sqlite (RC)** — the safe TS fallback; same Zod schemas as option 1. Loses on single-binary (SEA still 1.1, no recommended cross-build, ~115 MB) and on WS throughput/pub-sub; Fastify 6 is imminent.
4. **Bun + Elysia** — best day-one DX (`fromTypes()` OpenAPI, validated `.ws()` messages, Scalar built in) but 1.4 is frozen and 2.0 is beta with a changed WS API; only pick it if you accept building on `elysia@next` and re-testing Range/iOS media after every update.
5. **Rust 1.98 + Axum 0.8.9 + utoipa 5.5 + rusqlite/sqlx** — the most efficient and smallest binary, but the slowest path for a solo developer here; worth it only if you already write async Rust daily.
6. **Python 3.14 + FastAPI 0.141** — great docs DX, but 10–40x worse memory/latency in measured comparisons and no sane single-binary story across OSes.
7. **NestJS 12** — over-structured for a solo LAN game server; fresh v12 toolchain migration.

## 7. Stack-relevant design notes

**Buzzer fairness (the "ping kills the game" case).** Independent of stack, implement: (a) server-arrival timestamps only, never trust client clocks for ordering; (b) per-client clock-offset + RTT estimation via WS ping/pong (mini-NTP: take the smallest-RTT sample, resync every ~30–60 s and on tab visibility change); (c) "face-down" delivery: send the question/media early, then a server-scheduled `revealAt` so everyone sees the buzzer window at the same wall-clock instant; (d) after the first buzz, hold a fairness window of ~max(2×maxRTT, 150–250 ms), then rank buzzes by `clientPressTime − offset`, clamped to `[serverArrival − RTT, serverArrival]`, random tie-break within a few ms; (e) expose fairness data in the API (per-player RTT, applied correction) so hosts can audit. Bun's pub/sub, `ws.send` backpressure signal and `Bun.nanoseconds()` make (a)–(d) a few dozen lines; in Go use `time.Now()` + per-conn goroutines.

**.siq format (from `assets/siq_5.xsd` and the SIPackages README in VladimirKhil/SI, MIT).** ZIP with `content.xml` (required), `Images/`, `Audio/`, `Video/`, `Html/`, `[Content_Types].xml`; Cyrillic media names are URI-encoded. `content.xml`: `<package name id version="5" date difficulty language publisher restriction logo …>` → `tags`, `files` (name+hash), `info`, `global` (Authors/Sources) → `rounds/round(name, type)` → `themes/theme(name)` → `questions/question(price, type?)` with `params/param(name, type)` containing `item(type, isRef, placement, duration, waitForFinish)` content items (text/image/audio/video/html), optional `script/step` for custom types, `numberSet(minimum, maximum, step)` for stake questions, `right/answer+`, `wrong/answer*`. Legacy v4 `scenario/atom(type=text|image|video|voice|say|marker)` is deprecated but still present in the XSD — import both, export v5 only. Author's format article: script defines *how* to play, params carry the data; `answerType=select` + `answerOptions` for multiple choice.

**Cross-platform packaging reality check.** Go: trivial from one host. Bun: trivial from one host (~60 MB each). Rust: per-target toolchains or `cargo-zigbuild`. Node SEA: build on each OS (Stability 1.1, `useCodeCache/useSnapshot=false` for cross builds). Python: build on each OS.

## 8. Risks and mitigations for the recommended stack

- Bun 1.4 Rust port is 4 weeks old: pin 1.4.2, CI on win/mac/linux with `bun test`, keep 1.3.14 installer around; Hono code is portable to Node (`@hono/node-server` 2.1.1) if Bun regresses.
- Range handling depends on passing `Bun.file` bodies through untouched: add an integration test that asserts 206 + `Content-Range` for audio/video endpoints.
- `@hono/zod-openapi` is Zod-only; if the client prefers Valibot/ArkType use `hono-openapi` (Standard Schema) instead.
- Drizzle 1.0 GA will change casing/codec APIs; keep queries thin or use raw `bun:sqlite` for hot paths.
- Zip bombs and path traversal in user packs: enforce entry-count/size limits and normalize paths on import (yauzl exposes entry sizes before extraction).

- SIQ format: ZIP with content.xml (schema assets/siq_5.xsd, MIT repo VladimirKhil/SI), Images/, Audio/, Video/, Html/, [Content_Types].xml; package(version=5) -> rounds/round(type) -> themes/theme -> questions/question(price,type) with params/param(name,type) of item(type,isRef,placement,duration,waitForFinish), optional script/step, numberSet(min,max,step), right/answer+, wrong/answer*; legacy v4 scenario/atom(text|image|video|voice|say|marker) is deprecated.
- TS zip/xml options: fflate 0.8.3 (in-memory/streaming, 8 kB), yauzl 3.4.0 / yazl 3.3.1 (streaming), adm-zip 0.6.1, fast-xml-parser 5.11.1; Bun.Archive is tar/gzip only.
- Buzzer fairness is a protocol problem: use server-arrival timestamps, per-client RTT/clock-offset estimation (smallest-RTT sample), server-scheduled reveal instant, and a short post-first-buzz fairness window with RTT-clamped correction and random tie-break.
