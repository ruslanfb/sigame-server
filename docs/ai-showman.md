# ИИ-ведущий: проверка ответов через OpenRouter

Руководство для ведущих и операторов сервера. Что делает ИИ-ведущий, как его включить,
сколько это стоит и какие данные уходят наружу.

## Что это

В «Своей игре» текстовые ответы игроков проверяет ведущий. В нашем сервере ведущим может быть:

- **человек** — получает ответ игрока, список правильных ответов и комментарий автора пака, нажимает «верно»/«неверно»
  (можно с коэффициентом, например 0.5 — половина цены);
- **ИИ-ведущий** — та же задача выполняется языковой моделью через сервис [OpenRouter](https://openrouter.ai);
- **автопроверка** — встроенное сравнение строк, как в оригинальном SIGame (см. ниже). Работает всегда и без интернета.

Порядок проверки одного текстового ответа (`internal/ai.Composite`):

1. Ответы типа «число», «выбор варианта», «точка на картинке», «решает клиент» проверяются детерминированно
   (ИИ не участвует). Число — с допуском `±answerDeviation` из пака; точка — по расстоянию.
2. Если ответ после нормализации (регистр, ё/е, знаки препинания, лишние пробелы) **дословно совпадает** с одним из
   правильных ответов — «верно», с одним из заведомо неверных (поле `wrong` в паке) — «неверно». Без ИИ.
3. Иначе, если ИИ-ведущий настроен, ответ отправляется модели (таймаут 8 с, одна повторная попытка при ошибке сети
   или ограничении частоты запросов).
4. Если модель недоступна, не ответила вовремя или вернула мусор — применяется **автопроверка** (источник вердикта
   `fallback`), игра не останавливается.
5. Вердикты ИИ и автопроверки кэшируются в рамках вопроса: два игрока с одинаковым ответом получат одинаковое решение.

### Автопроверка (как в SIGame)

Ответ считается верным, если сходство букв (1 − расстояние Левенштейна / длина) с любым из правильных ответов
**≥ 0.81** (порог оригинального SIGame), при этом:

- ответы, состоящие из одних цифр, должны совпадать точно («1812» ≠ «1813»);
- если ответ ближе к одному из заведомо неверных ответов, чем к правильным, — «неверно»;
- те же слова в другом порядке («Пушкин Александр» / «Александр Пушкин») — «верно»;
- часть правильного ответа в скобках необязательна: «Пушкин (Александр Сергеевич)» принимает «Пушкин».

Автопроверка **не** понимает синонимов, транслитерации («Pushkin» вместо «Пушкин») и ответов только фамилией
(«Пушкин» вместо «Александр Пушкин») — такие случаи она помечает как *неуверенные* (см. ниже), а ИИ-ведущий решает их
правильно.

## Что значит «не уверен» (uncertain)

И ИИ, и автопроверка могут вернуть вердикт **uncertain**: ответ не принят (очки не начислены), но судья честно
сообщает, что не может решить. Примеры: ответ похож на правильный, но сходство чуть ниже порога («Парис» / «Париж»);
дана только фамилия, а автор требует полное имя; ответ подходит и под правильный, и под заведомо неверный вариант.

Что происходит дальше, определяет настройка комнаты:

- **есть ведущий-человек** — вопрос передаётся ему (как обычная проверка в SIGame, таймер `ShowmanDecision` 30 с);
- **ведущего-человека нет** — комната применяет результат автопроверки (для неуверенного вердикта это «неверно»).

Игрок в любом случае может подать апелляцию («Я прав!») — она работает так же, как в SIGame: голосуют остальные игроки.

## Как получить ключ OpenRouter

1. Зарегистрируйтесь на <https://openrouter.ai> (почта, Google или GitHub).
2. Пополните баланс: **Credits** → *Add credits* (принимаются банковские карты и криптовалюта; для домашней игры
   достаточно нескольких долларов, см. раздел «Стоимость»).
3. Создайте ключ: **Keys** → *Create key*. Задайте имя (например `sigame`) и при желании лимит расходов на ключ
   (*Credit limit*) — это защита от неожиданных трат.
4. Скопируйте ключ (`sk-or-v1-…`) — он показывается один раз.

Рекомендуется завести отдельный ключ для сервера и не использовать его больше нигде.

## Настройка сервера

Переменные окружения (можно также задать в `config.yaml`, см. `docs/ops.md`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `OPENROUTER_API_KEY` | пусто — ИИ выключен | Ключ OpenRouter. Пустое значение = играем только с автопроверкой/человеком |
| `OPENROUTER_MODEL` | `tencent/hy4-preview` | ID модели на OpenRouter. Нужна текстовая модель; желательно с поддержкой *structured outputs* |
| `OPENROUTER_BASE_URL` | `https://openrouter.ai/api/v1` | Менять только для прокси или совместимого self-hosted API |
| `SIGAME_AI_TIMEOUT` | `8s` | Таймаут одного запроса (вместе с повтором). По истечении — автопроверка |
| `SIGAME_AI_TEMPERATURE` | `0` | Температура модели |
| `SIGAME_AI_MAX_TOKENS` | `200` | Лимит токенов ответа модели |
| `SIGAME_PUBLIC_URL` | пусто | Используется как заголовок `HTTP-Referer` — OpenRouter показывает его в статистике приложения |

Ключ **никогда** не пишется в логи и не отдаётся через API. Проверить настройку можно запросом
`GET /api/v1/ai/status` (настроен ли ключ, модель, последняя ошибка и задержка) и `POST /api/v1/ai/test`
(один пробный запрос к модели: «Столица Франции» → «Paris» должен быть принят). Список доступных моделей —
`GET /api/v1/ai/models`.

### Выбор модели

Подходит любая текстовая модель. Что важно:

- **Русский язык.** Модель должна хорошо понимать русский (все крупные современные модели понимают).
- **Structured outputs.** Сервер просит модель отвечать строго по JSON-схеме (`response_format: json_schema`).
  Если модель этого не умеет, сервер один раз получает ошибку, запоминает это и дальше просит «просто JSON»,
  извлекая объект из текста. Работает, но чуть менее надёжно.
- **Скорость.** Проверка ответа — часть игрового темпа. Модели с «размышлением» (reasoning) отвечают дольше;
  для судейства достаточно быстрой недорогой модели.
- **Цена.** См. ниже. На странице модели на openrouter.ai указана стоимость за 1M токенов.

Список моделей с поддержкой structured outputs:
<https://openrouter.ai/models?supported_parameters=structured_outputs>.

## Стоимость и лимиты

Один запрос на проверку — это системная инструкция (~450 токенов) + вопрос, ответы и комментарий (обычно 50–200 токенов)
+ короткий ответ модели (~30 токенов). Итого **≈ 600–800 токенов на один ответ игрока**. Запросы делаются только для
текстовых ответов, которые не совпали дословно; числа/варианты/точные попадания бесплатны.

Ориентир: игра на 4–6 игроков и 60–90 вопросов — порядка 100 проверок, то есть ~70 000 токенов. Для моделей с ценой
$0.1–1 за 1M входных токенов это **несколько центов за игру**. Точную цену смотрите на странице модели; расход виден
в разделе *Activity* на openrouter.ai, а количество токенов — в `GET /api/v1/ai/status` (`totalTokens`).

Ограничения:

- **Лимит запросов (HTTP 429).** У бесплатных моделей (`:free`) он жёсткий (десятки запросов в минуту и небольшой
  дневной лимит). Сервер один раз повторяет запрос через 0,5 с, затем применяет автопроверку. Для игры с людьми
  берите платную модель.
- **Баланс (HTTP 402).** При нулевом балансе все запросы отклоняются — сервер работает дальше на автопроверке,
  в `GET /api/v1/ai/status` будет `lastError` с кодом 402.
- **Таймаут.** 8 с на запрос. Медленная модель = задержки между ответом и вердиктом; при превышении — автопроверка.
- Комментарий автора пака к вопросу (`showmanComments`) передаётся модели как авторитетное указание: «принимать только
  полное имя», «засчитывать любой из городов» и т. п. Это лучший способ управлять строгостью судьи.

## Конфиденциальность

Модели отправляется **только**:

- язык пака, название темы и текст вопроса (без медиафайлов);
- список правильных и заведомо неверных ответов из пака;
- комментарий автора для ведущего;
- сам ответ игрока (обрезается до 500 символов).

**Не отправляются**: имена игроков, код комнаты, счёт, IP-адреса, картинки/аудио/видео, содержимое других вопросов.
Ответ игрока передаётся как данные внутри разделителей, модели явно запрещено выполнять любые «инструкции» из него.

OpenRouter пересылает запрос провайдеру модели. Политика хранения данных зависит от провайдера; в настройках
аккаунта OpenRouter (*Settings → Privacy*) можно запретить провайдеров, которые обучаются на данных или хранят
логи, а также включить только ZDR-эндпоинты (zero data retention). Сервер со своей стороны логирует вердикты только
на уровне `DEBUG` (без ключа).

## Типичные проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| Все вердикты приходят с источником `fallback` | Ключ не задан или недействителен (`lastError: HTTP 401`) | Проверить `OPENROUTER_API_KEY`, вызвать `POST /api/v1/ai/test` |
| `lastError: HTTP 402` | Закончились кредиты | Пополнить баланс |
| `lastError: HTTP 429` | Лимит запросов (обычно у бесплатных моделей) | Сменить модель на платную |
| `lastError: ... timed out` | Модель слишком медленная | Выбрать более быструю модель или увеличить `SIGAME_AI_TIMEOUT` |
| `lastError: HTTP 400 ... model not found` | Неверный ID модели | Взять ID из `GET /api/v1/ai/models` |
| Судья слишком строгий/мягкий | Модель судит по правилам SIGame | Уточнить `showmanComments` в паке или добавить варианты в `right`/`wrong` |
