# Паки вопросов: модель, импорт и экспорт .siq

Документ для авторов паков и для тех, кто переносит паки из SIGame (SIQuester, SIOnline) на этот сервер.
Модель пака сервера — надмножество формата SIQ версии 5, поэтому любой пак SIGame импортируется без потерь,
а экспорт всегда даёт файл `.siq` версии 5, который читают SIGame, SIOnline и SIQuester.

Технические детали формата: `docs/research/02-siq-format.md`, схема `testdata/siq-spec/siq_5.xsd`.
Код: `internal/siq` (импорт/экспорт), `internal/packs/model.go` (модель).

## 1. Что такое пак

Пак — это набор вопросов, организованный в иерархию **пак → раунды → темы → вопросы**, плюс медиафайлы
(картинки, звук, видео, HTML) и метаданные. В JSON-API пак выглядит так (сокращённо):

```json
{
  "id": "0190a5f3-…", "name": "Тестовый пак", "language": "ru-RU", "difficulty": 5,
  "restriction": "12+", "date": "07.07.2026", "publisher": "…", "contactUri": "https://…",
  "logoMediaId": "2620c885…", "tags": ["Кино", "Музыка"],
  "info": { "authors": ["Иван Петров"], "sources": ["…"], "comments": "…", "showmanComments": "…" },
  "rounds": [ { "id": "…", "name": "1-й раунд", "type": "standard", "info": {}, "themes": [ … ] } ],
  "extra": { "globalAuthors": [ … ], "globalSources": [ … ] },
  "siqId": "a16f96e7-…"
}
```

| Поле пака | Назначение |
|---|---|
| `name` | Название (обязательно, до 350 символов) |
| `language` | BCP-47, например `ru-RU`, `en-US` |
| `difficulty` | Сложность 0–10 (0 = не указана) |
| `restriction` | Возрастное ограничение в свободной форме (`12+`, `18+`) |
| `date`, `publisher`, `contactUri` | Свободные строки: дата создания, издатель, контакт автора |
| `logoMediaId` / `logoUrl` | Логотип: медиа на сервере **или** внешняя ссылка |
| `tags` | До 10 тем пака (для поиска в библиотеках) |
| `info` | Авторы, источники, комментарий и комментарий для ведущего (см. ниже) |
| `extra.globalAuthors`, `extra.globalSources` | Справочники авторов/источников SIQ (`<global>`); хранятся как есть для обратного экспорта |
| `siqId` | Оригинальный `id` из `.siq`, если пак импортирован |

### Блок `info`

Есть у пака, раунда, темы и вопроса и **наследуется вниз**: раунд без авторов считается написанным авторами пака.

| Поле | Кто видит | Смысл |
|---|---|---|
| `authors` | все | До 10 строк. Строка может быть ссылкой `@<id>` на запись `extra.globalAuthors` |
| `sources` | все | До 10 строк; ссылка `@<id>#<уточнение>` (например, `#с.256`) на `extra.globalSources` |
| `comments` | все | Показывается на экране по окончании вопроса (для вопроса) или как описание (для пака/раунда/темы) |
| `showmanComments` | только ведущий | Подсказка ведущему; игрокам не отправляется |

## 2. Раунды и темы

| Тип раунда | В `.siq` | Как играется |
|---|---|---|
| `standard` | `standart` (по умолчанию), псевдоним `table` | Классическая таблица «темы × стоимости»; игрок-выбирающий открывает ячейку |
| `final` | `final`, псевдоним `themeList` | Финал: игроки по очереди убирают темы, пока не останется одна; играется **только первый вопрос** оставшейся темы, его `price` не важен — каждый делает скрытую ставку |

Тема (`theme`) — это имя, `info` и список вопросов (до 30). В обычном раунде вопросы одной темы обычно идут
с возрастающей стоимостью (100, 200, …); в финале в теме достаточно одного вопроса со стоимостью `0`.

## 3. Вопрос

```json
{
  "id": "…", "price": 300, "type": "secret",
  "params": {
    "theme": "Новая тема",
    "price": { "min": 100, "max": 1000, "step": 200 },
    "selectionMode": "any",
    "question": [ { "type": "text", "text": "Текст вопроса" } ],
    "answer":   [ { "type": "image", "mediaId": "8bf88c61…" } ],
    "answerType": "select",
    "answerOptions": [ { "label": "A", "content": [ { "type": "text", "text": "Вариант 1" } ] } ],
    "answerDeviation": 5,
    "answerDurationMs": 15000
  },
  "right": ["Ответ", "Альтернативный ответ"],
  "wrong": ["Неверная версия"],
  "info": { "comments": "…" }
}
```

* `price` — номинал. `-1` — **пустая ячейка** (вопрос удалён из таблицы, но место осталось). В финале обычно `0`.
* `right` — принимаемые ответы (хотя бы одна строка; для `select` — метка варианта, для `number` — число,
  для `point` — `x,y,ratio`). `wrong` — заведомо неверные версии, помогают ведущему/ИИ отклонять ответ.
* `params.question` — содержимое вопроса, воспроизводится по порядку. `params.answer` — необязательное
  содержимое ответа (медиа или текст); если его нет, показывается `right[0]`.
* `script` и `extraParams` — сохранённые «как есть» пользовательский сценарий и неизвестные параметры SIQ.
  Движок их не исполняет; они нужны для обратного экспорта.

### 3.1 Типы вопросов

| `type` | Имя в SIQ v4 | Дополнительные параметры | Правила |
|---|---|---|---|
| `simple` (или пусто) | `simple` / нет `<type>` | — | Вопрос на кнопку: кто первый нажал, тот отвечает; неверно — минус номинал, остальные могут жать |
| `stake` | `auction` | — | Торги: ставки по кругу от номинала, ва-банк перекрывается только большим ва-банком; отвечает победитель торгов, цена = ставка |
| `stakeAll` | — | — | Все игроки делают скрытую ставку и отвечают письменно; каждый выигрывает/проигрывает свою ставку (режим финала) |
| `secret` | `cat`, `bagcat knows=after` | `theme`, `price`, `selectionMode` | «Кот в мешке»: открывший отдаёт вопрос другому игроку; тема и стоимость объявляются **после** передачи |
| `secretPublicPrice` | `bagcat knows=before` | `theme`, `price`, `selectionMode` | То же, но тема и стоимость объявляются **до** передачи |
| `secretNoQuestion` | `bagcat knows=never` | `price`, `selectionMode` | Вопроса нет: получивший просто получает стоимость |
| `noRisk` | `sponsored` | — | Отвечает только открывший; верно — +2×номинал, неверно — 0 |
| `forAll` | — | — | Все отвечают письменно на ± номинал |
| `custom` или любое другое имя | любое неизвестное | произвольные `extraParams` | Играется ведущим вручную (пауза / управляемый режим) |

Параметры «секретных» вопросов:

* `theme` — собственная тема вопроса (для `secretNoQuestion` не используется).
* `price` — набор стоимостей, из которого выбирает получивший вопрос:
  `min = max = N` — фиксированная стоимость N; `min = max = 0` — на выбор минимум или максимум раунда;
  `min < max, step > 0` — ряд `min, min+step, … ≤ max`; `step = 0` (или `step = max − min`) — только два крайних значения.
* `selectionMode` — `exceptCurrent` (обязан отдать другому, по умолчанию) или `any` (может оставить себе).

### 3.2 Типы ответов (`params.answerType`)

| Значение | Что вводит игрок | Что лежит в `right` | Доп. параметры |
|---|---|---|---|
| `text` (пусто) | свободный текст | варианты ответа | — |
| `select` | выбор варианта | **метка** варианта (`C`) | `answerOptions`: варианты с метками `A`, `B`, `C`…; каждый вариант — список содержимого (обычно один текст или картинка); нужно ≥ 2 |
| `number` | целое число | число | `answerDeviation` — допустимое отклонение ± |
| `point` | точка на последней картинке вопроса | `x,y,ratio` | `answerDeviation` — допуск расстояния |
| `client` | решает клиент | — | — |

`answerDurationMs` переопределяет таймер на ответ для конкретного вопроса (в `.siq` хранится в секундах).

## 4. Содержимое (ContentItem)

Элемент списка `question`, `answer` или варианта ответа:

| Поле | Значения | Смысл |
|---|---|---|
| `type` | `text`, `image`, `audio`, `video`, `html` | Вид фрагмента |
| `text` | строка (до 1500 символов) | Для `text` |
| `mediaId` | sha256 hex | Файл на сервере (загружен через API медиа или импортирован из `.siq`) |
| `url` | абсолютный URL | Внешний ресурс вместо `mediaId`; игроки должны разрешить загрузку из внешних источников |
| `placement` | `screen`, `replic`, `background` | Где показывать: экран (по умолчанию для всего, кроме аудио), реплика ведущего (только текст), фон (только аудио — по умолчанию) |
| `durationMs` | мс | Сколько держать фрагмент на экране; `0` — автоматически (по длительности медиа / длине текста) |
| `noWait` | `true` | Не ждать окончания фрагмента, а сразу запускать следующий (текст + фоновая музыка, несколько картинок разом) |

Ровно одно из `text` / `mediaId` / `url` заполнено. Фрагменты воспроизводятся последовательно, `noWait` объединяет
фрагмент со следующим.

## 5. Медиа

* Хранилище адресует файлы по содержимому (`sha256`); один и тот же файл в двух паках хранится один раз.
* Поддерживаемые форматы: изображения `png`, `jpg`, `gif`, `webp`; аудио `mp3`, `ogg`, `m4a`, `wav`; видео `mp4`, `webm`; `html`.
  Лимиты размера задаёт хранилище (см. `docs/ops.md`).
* HTML-фрагменты показываются во фрейме на стороне клиента; клиенты могут запрещать HTML — при импорте такие
  вопросы отмечаются в отчёте (`htmlContent`).
* Логотип пака — обычная картинка (`logoMediaId`) или внешняя ссылка (`logoUrl`).

## 6. Импорт `.siq`

`POST /api/v1/packs/import` принимает файл `.siq` версий **3, 4 и 5**. Результат — новый пак и **отчёт импорта**.

### 6.1 Что происходит с архивом

1. Проверяются лимиты безопасности: не более 5000 записей, суммарный распакованный размер ≤ 2 ГиБ,
   подозрительная степень сжатия (> 200× для файлов больше 1 МиБ) и пути вида `../`, абсолютные пути отвергаются;
   `content.xml` ≤ 32 МиБ.
2. `content.xml` ищется в корне архива или внутри одной вложенной папки (без учёта регистра). BOM и любое
   пространство имён XML (`ygpackage3.0`, `siq_5`, с префиксами или без) принимаются.
3. Медиафайлы ищутся по папкам `Images/`, `Audio/`, `Video/`, `Html/`. Имя из XML сопоставляется с именем записи
   архива во всех известных вариантах: как есть, после percent-декодирования (`%D0%A1…` → `С…`, `%20` → пробел,
   `+` остаётся плюсом), в NFC и NFD (архивы с macOS), без учёта регистра, с отброшенным ведущим `@`, а для записей
   без флага UTF-8 — ещё и в кодировке cp866 (старые Windows-архиваторы). Файл в другой папке или в корне тоже
   находится (с предупреждением `extraFolderEntry`).
4. Каждый найденный файл потоково загружается в хранилище (kind проверяется по типу фрагмента). Один и тот же файл
   загружается один раз, сколько бы вопросов на него ни ссылались.
5. `Texts/authors.xml`, `Texts/sources.xml` (v4) и `<global>` (v5) попадают в `extra`; `[Content_Types].xml` и
   `quality.marker` игнорируются.

**Отсутствующий или отвергнутый медиафайл не ломает импорт**: фрагмент удаляется из вопроса, в отчёт добавляется
запись уровня `error` (`mediaMissing`, `mediaTooLarge`, `mediaUnsupported`) с путём до вопроса, счётчик
`stats.mediaMissing` увеличивается. Пак сохраняется и играется без этого фрагмента.

Режим `skipMedia` (предпросмотр/валидация) не загружает файлы: фрагменты остаются в вопросах с пустым `mediaId`,
а отчёт по-прежнему показывает, какие файлы не нашлись. Такой пак нельзя сохранять.

### 6.2 Преобразование v4 → v5

Паки версий 3 и 4 (`<type>` + `<scenario>`) переводятся в модель v5 в точности как это делает SIGame:

| v4 | Результат |
|---|---|
| `<type name="simple">` или нет `<type>` | `simple` |
| `auction` | `stake` |
| `sponsored` | `noRisk` |
| `cat` (`theme`, `cost`) | `secret`, `selectionMode = exceptCurrent` |
| `bagcat knows=after` / без `knows` | `secret` |
| `bagcat knows=before` | `secretPublicPrice` |
| `bagcat knows=never` | `secretNoQuestion` (сценарий отбрасывается, тема не нужна) |
| `cost`: `N`, `0`, `[a;b]`, `[a;b]/h` | `price`: `{N,N,0}`, `{0,0,0}`, `{a,b,0}`, `{a,b,h}`; нечитаемое значение → номинал вопроса + предупреждение `invalidNumberSet` |
| `self=true` / `false` | `selectionMode = any` / `exceptCurrent` |
| другое имя типа | пользовательский тип с тем же именем, его `<param>` → `extraParams` (`unknownQuestionType`) |
| `<atom>` до первого `<atom type="marker"/>` | `params.question`; после маркера — `params.answer` (следующие маркеры игнорируются) |
| `<atom type="say">` | текст с `placement = replic` |
| `<atom type="voice">` / `audio` | аудио (`background`) |
| `image`, `video`, `html` | как есть |
| `@имя` | файл из пакета; без `@` — внешняя ссылка (`externalUrl`) |
| `time="-1"` | `noWait = true` |
| `time="N"` | `durationMs = N × 1000` (дробные секунды сохраняются) |
| `Texts/authors.xml`, `Texts/sources.xml` | `extra.globalAuthors` / `extra.globalSources` |

Смешанные документы (v5 `<params>` рядом с v4 `<type>`) и устаревшие имена типов в атрибуте `type`
(`auction`, `sponsored`, `cat`, `bagcat`, `withButton`, `forYourself`) тоже понимаются.

### 6.3 Отчёт импорта

```json
{
  "version": 4,
  "entries": [
    { "level": "error",   "code": "mediaMissing", "path": "/rounds/0/themes/1/questions/5/params/question/0",
      "message": "media file \"nope.png\" not found in Images/; item dropped" },
    { "level": "warning", "code": "emptyRight",   "path": "/rounds/0/themes/0/questions/8", "message": "question has no right answer" },
    { "level": "info",    "code": "v4Upgraded",   "message": "package version 4: 17 question(s) converted to the v5 model" }
  ],
  "stats": { "rounds": 2, "themes": 4, "questions": 20, "byType": { "simple": 12, "stake": 1, "secret": 3 },
             "mediaImported": 4, "mediaMissing": 1, "bytes": 1842315 }
}
```

| Код | Уровень | Значение |
|---|---|---|
| `mediaMissing` | error | Файл не найден в архиве (или не читается) — фрагмент удалён |
| `mediaTooLarge` | error | Хранилище отвергло файл по размеру — фрагмент удалён |
| `mediaUnsupported` | error / warning | Неподдерживаемый тип файла или несоответствие типу фрагмента (error, фрагмент удалён); неизвестный `type` фрагмента (warning, показан как текст) |
| `unknownQuestionType` | warning | Пользовательский тип — играется вручную |
| `unknownParam` | warning | Неизвестный параметр или значение сохранены как есть |
| `invalidNumberSet` | warning | Стоимость «кота» не разобрана — взят номинал |
| `invalidPrice` | warning | Нечитаемый `price` — взят 0 |
| `emptyRight` | warning | У играемого вопроса нет правильного ответа |
| `unknownRoundType` | warning | Неизвестный тип раунда — считается обычным |
| `unsupportedVersion` | warning | Версия новее 5 — разобрана по правилам v5 |
| `extraFolderEntry` | warning / info | Медиа найдено не в своей папке (warning); лишняя запись архива проигнорирована (info) |
| `customScript` | info | У вопроса есть `<script>`; он сохранён, но не исполняется |
| `v4Upgraded` | info | Пак старой версии преобразован |
| `htmlContent` | info | В вопросе есть HTML-фрагмент |
| `externalUrl` | info | Фрагмент или логотип ссылается на внешний URL |
| `truncated` | warning | Значение обрезано по лимиту (зарезервировано; лимиты применяет валидация пака) |

## 7. Экспорт `.siq`

`GET /api/v1/packs/{id}/export` отдаёт архив версии 5:

* `content.xml` — UTF-8 с BOM, объявление `<?xml version="1.0" encoding="utf-8"?>`, пространство имён
  `siq_5.xsd`, без отступов, сжатие deflate. Порядок элементов как у SIQuester: `tags`, `global`, `files`, `info`, `rounds`.
* Атрибуты пака: `name`, `version="5"`, `id` (`siqId`, иначе `id` пака), `restriction`, `date`, `publisher`, `contactUri`,
  `difficulty` (если > 0), `logo` (`@файл` или URL), `language`.
* Раунд: `type` пишется только для финала (`final`). Вопрос: `type` пишется для всех, кроме `simple`; `<params>` есть всегда;
  `<right>` всегда содержит хотя бы один `<answer>`; `<wrong>` — если есть.
* Фрагменты: `type` опускается для текста; `isRef="True"` для медиа с сервера; `placement` — только если отличается от
  умолчания (для аудио всегда `background`); `duration` в формате `hh:mm:ss` (миллисекунды округляются до секунд);
  `waitForFinish="False"` при `noWait`. `answerDuration` пишется в целых секундах.
* Медиафайлы лежат в `Images/`, `Audio/`, `Video/`, `Html/` без сжатия, с флагом UTF-8 в именах. Имя берётся из
  исходного имени файла (`originalName`), из него удаляются `/ \ % # ?` и управляющие символы, расширение приводится к
  фактическому типу файла; одинаковые имена получают суффиксы `-2`, `-3`… Файл без имени называется по первым 16 символам
  его идентификатора.
* `<files>` содержит SHA-256 (заглавный hex) каждого медиафайла; `[Content_Types].xml` — однострочный вариант
  `si/xml` для совместимости со старыми клиентами. `quality.marker` и `Texts/*.xml` не пишутся.
* Экспорт завершается ошибкой, если какой-то `mediaId` пака отсутствует в хранилище.

Порядок записей и имена детерминированы: один и тот же пак экспортируется в один и тот же архив.

## 9. Лимиты

| Лимит | Значение | Где применяется |
|---|---|---|
| Записей в архиве | 5000 | импорт |
| Распакованный размер архива | 2 ГиБ | импорт |
| Степень сжатия записи (> 1 МиБ) | 200× | импорт |
| `content.xml` | 32 МиБ | импорт |
| Размер медиафайла, форматы | по настройкам хранилища | хранилище (`mediaTooLarge`, `mediaUnsupported`) |
| Раундов / тем в раунде / вопросов в теме | 50 / 30 / 30 | валидация пака |
| Фрагментов в списке, шагов сценария | 30 | валидация пака |
| Текст (названия, ответы) / текст фрагмента | 350 / 1500 символов | валидация пака |
| Теги, авторы, источники | 10 | валидация пака |

Лимиты модели совпадают с `PackageLimits` игрового сервера SIGame: пак, проходящий валидацию здесь, загружается и в SIGame.
